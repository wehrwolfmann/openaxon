## Постановка: два разных «установщика», не путать

| Что | Файл | Технология | Нужен ли для установки |
|---|---|---|---|
| Онлайн-обёртка | `RazerAxonInstaller.exe` | нативный стаб + .NET Framework 4.8 движок + WPF-интерфейс | нет, если setup уже скачан |
| Собственно setup приложения | `RazerAxonSetup_2.9.1.0.exe` | Inno Setup 6.7 | **да, это он ставит Axon** |

Майский вывод: WPF-интерфейс обёртки под Wine крашится на экране лицензии
(`TextBlockTextPlugin` / `0x80131623`), поэтому рабочий путь — **брать Inno-setup и
ставить его напрямую в тихом режиме**. Параметры Razer публикует сам, в манифесте:

```
/SP- /VERYSILENT /DIR="%programfiles(x86)%\Razer\Razer Axon" /SUPRESSMSGBOXES /NORESTART
```

## Журнал заходов

Формат: что менял → что получилось → доказательство (строка лога/файл).

### Заход 0 — исходное состояние

Система вычищена. Симптом, о котором сообщил пользователь на прежнем (уже снесённом)
префиксе: `rundll32.exe — This application could not be started.`

**На чистом префиксе этот симптом ни разу не воспроизвёлся** — ни при установке Axon,
ни при запуске приложения, ни при установке Razer Central. Наиболее правдоподобное
объяснение (это рассуждение по уликам, а не замер): прежний префикс остался **с
недоделанной установкой .NET**. Улика — в логе winetricks видно, что перед установкой
`dotnet40` он **удаляет обе копии `mscoree.dll`**:

```
Executing rm -f …/prefix/dosdevices/c:/windows/syswow64/mscoree.dll
Executing rm -f …/prefix/dosdevices/c:/windows/system32/mscoree.dll
Executing w_do_call dotnet40
```

Если на этом месте процесс прерван (а прерваться ему есть на чём — см. заход 8 про
вечный деадлок `wineserver -w`), префикс остаётся **без wine-mono и без настоящего .NET
одновременно**. В таком префиксе любой запуск управляемого кода — в том числе через
`rundll32` — падает с «This application could not be started», а версия Windows остаётся
той, которую winetricks выставил на промежуточном шаге. Это разом объясняет и `rundll32`,
и «семёрку».

Практический вывод для рецепта: **`winetricks dotnet48` в этом префиксе либо доводить до
конца, либо не начинать вовсе**; прерванный на середине он оставляет неработоспособный
префикс, который проще пересоздать, чем чинить.

### Заход 2 — Inno-setup 2.9.1.0 напрямую, тихий режим, свежий префикс без единой правки

Что делал (ровно те параметры, которые Razer публикует в собственном манифесте):

```bash

wine ~/Загрузки/axon-installer-2026-08-10/RazerAxonSetup_2.9.1.0.exe \
```

Результат — **пошло сразу**: развернулся распаковщик
`…\Temp\is-*.tmp\RazerAxonSetup_2.9.1.0.tmp /SL5=$2004E,62315557,1126912,…`
и начал наполнять `drive_c/Program Files (x86)/Razer/Razer Axon/`.
Ни `winetricks`, ни `dotnet48`, ни смена версии Windows для этого шага не потребовались.

Распаковка идёт ~1,5 минуты (под трассировкой `+seh` заметно медленнее), выкладывается
**≈165 МБ / 430 файлов**, после чего Inno переходит к шагу «после установки».

### Заход 3 — что делает Inno ПОСЛЕ распаковки: тянет WebView2 из сети

⭐ Это и есть то самое «что-то было с интернетом». В 2.9.1.0 Razer **вшил в setup
онлайн-загрузчик WebView2** и запускает его сам (в мае рантайм ставили руками
отдельным файлом):

```
C:\Program Files (x86)\Razer\Razer Axon\MicrosoftEdgeWebview2Setup.exe /silent /install
  └─ C:\Program Files (x86)\Microsoft\Temp\EU*.tmp\MicrosoftEdgeUpdate.exe /silent /install
        appguid={F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}
        &appname=Microsoft%20Edge%20Webview2%20Runtime&needsadmin=prefers
```

То есть setup Axon **не самодостаточен**: это тонкая обёртка вокруг Microsoft Edge Update,
которая качает Evergreen-рантайм WebView2 (~190 МБ) с серверов Microsoft. Без интернета
(или при заблокированных `msedge.api.cdp.microsoft.com` / `msedge.b.tlu.dl.delivery.mp.microsoft.com`)
этот шаг тихо не отрабатывает — и приложение потом рисует пустое окно, потому что весь
интерфейс Axon это WebView2.

Побочный шум Wine на этом шаге (не ошибки установки, само по себе не мешает):

```
fixme:seh:WerRegisterCustomMetadata (L"EdgeUpdateDllVersion", L"1.3.167.21") stub
err:combase:RoGetActivationFactory Failed to find library for
    L"Windows.System.Diagnostics.Telemetry.PlatformTelemetryClient"
err:ole:com_get_class_object no class object {cecddd22-2e72-4832-9606-a9b0e5e344b2} …
err:ole:CoSetProxyBlanket -- failed with 0x80004002
```

### Заход 5 — контрольный: тот же setup под Windows 7

Чтобы проверить гипотезу пользователя не рассуждением, а замером, поднят **второй
префикс** и в нём принудительно выставлена семёрка:

```bash
export WINEPREFIX="$HOME/.local/share/openaxon-test/prefix-win7"
WINEARCH=win64 wineboot --init
winecfg -v win7          # → ProductName = "Microsoft Windows 7"
wine …/RazerAxonSetup_2.9.1.0.exe /SP- /VERYSILENT '/DIR=…' /SUPRESSMSGBOXES /NORESTART
```

Результат: **установка не состоялась.** Папка `Program Files (x86)\Razer` так и не
появилась (под win10 она возникала на 16-й секунде), а вместо этого установщик поднял
модальное окно с классической ошибкой Inno Setup:

> **This program does not support the version of Windows your computer is running.**

Снимок-доказательство: `~/Изображения/Screenshots/axon-2910-установщик-под-win7-ошибка.png`
(окно `Error`, 299×82). После нажатия «OK» установщик просто завершается, ничего не
установив.

⭐ **Это ровно тот симптом, который наблюдал пользователь** («при Windows 7 установщик
молча не запускается»), и вот почему он выглядит «молчаливым»:

* запуск идёт с `/VERYSILENT`, поэтому никакого окна установки нет — на экране
  появляется только крошечный безымянный `Error` размером 299×82, который легко
  не заметить или принять за системный;
* ⚠️ **Razer опечатался в собственных параметрах**: в манифесте написано
  `/SUPRESSMSGBOXES`, тогда как настоящий ключ Inno — `/SUPPRESSMSGBOXES` (два `p`).
  Опечатанный ключ Inno игнорирует, так что окна сообщений **не подавляются**. При
  headless-запуске (без видимого рабочего стола) установщик из-за этого не «падает»,
  а **зависает навсегда на невидимом модальном окне** — внешне неотличимо от «молча
  ничего не делает».

Вывод замера: **версия Windows решает исход установки, но проверку делает сам Inno-setup
(поле `MinVersion` в его `[Setup]`), а не сервер Razer.** Это отдельная, вторая по счёту
привязка к версии Windows — в мае была известна только серверная (пустой каталог при
`osver=7`).

### Заход 6 — запуск установленного приложения

```bash
cd "$WINEPREFIX/drive_c/Program Files (x86)/Razer/Razer Axon" && wine RazerAxon.exe
```

Приложение **стартует** и доходит до попытки входа:

```
Program.cs:Main   App start************************************
Program.cs:Main   startup args = -wrongaccess,isAdmin:True,userName:alexander,version:2.9.1.0
Program.cs:TryLoginAsync   Start userLogin
```

Дальше упирается в отсутствие Razer Central:

```
UserManager.cs:RegisterForUpdateAsync   Check update failed.
System.IO.IOException: Could not establish the connection.
 ---> System.TimeoutException: The operation has timed out.
   at Razer.ServiceClientBase.RazerClientBase.Connect(TimeSpan timeout)
   at Razer.Updater.UpdateClient.RegisterForUpdates(ProductDetails details)
```

Это **ожидаемо и не является дефектом установки**: манифест Razer ставит перед Axon
обязательный модуль `Natasha` = **Razer Central 7.23.0.1220** (`installation_priority`
300 против 32765 у самого Axon), а рецепт выше ставит только Axon. Именно к службе
Razer Central и стучится `RazerClientBase.Connect`.

Попутно `startup args = -wrongaccess`: Axon перезапускает сам себя с этим ключом,
потому что Wine рапортует `isAdmin:True`. На работу приложения это не влияет.

Ссылка берётся из того же манифеста (проверено сегодня, 2026-08-11 — и хеш `N82uNskI`,

Запуск `wine RazerCentral_v7.23.0.1220.exe /silent` — **ключ `/silent` не соблюдается**:

### Заход 8 — `winetricks -q dotnet48` и почему он «зависает»

⭐ **Найдена настоящая причина деадлока, который в майском документе списали на «известный
баг winetricks».** Баг не в winetricks. Дело в том, что установка WebView2 (заход 3)
оставляет в префиксе **резидентный процесс**:

```
C:\Program Files (x86)\Microsoft\EdgeUpdate\MicrosoftEdgeUpdate.exe /c
```

Он не завершается сам и живёт в префиксе бесконечно (в замере — 1010 с и продолжал бы).
А winetricks на каждом шаге выполняет `wineserver -w`, который по определению ждёт
завершения **всех** процессов префикса:

```
warning: Running /usr/bin/wineserver -w. This will hang until all wine processes
in prefix=… terminate
```

Итог: любой verb winetricks, выполненный в префиксе ПОСЛЕ установки Axon, встаёт намертво.
Снятие ровно этого процесса (по PID своего экземпляра, не по имени) немедленно разблокирует
winetricks и установка .NET идёт дальше.

Порядок шагов, который снимает проблему целиком: **ставить `dotnet48` ДО Axon**, а не после.

Второе наблюдение из лога — как winetricks обращается с версией Windows:

```
Executing w_do_call dotnet40
win10                          ← запомнил текущую версию префикса
Executing w_do_call winxp
Executing wine winecfg -v winxp64   ← временно опустил до XP ради dotnet40
```

То есть по ходу установки версия префикса опускается (winxp64 → далее win7), и если
процесс прервать или если winetricks не восстановит значение, префикс остаётся с чужой
версией Windows. Вот откуда берётся та самая «семёрка по умолчанию» из гипотезы —
её оставляет winetricks, а не `wineboot`.

### Заход 9 — окна нет вообще: Razer Central обязателен для ЛЮБОГО интерфейса

Дата: 2026-08-12. Префикс замера: `~/.local/share/openaxon-test/prefix` (Axon 2.9.1.0
уже установлен заходом 2).

Сначала исправлена методическая ошибка захода 6: там Axon запускали как
`wine RazerAxon.exe`, **без ключа `-showui`**. Собственный лаунчер проекта
(`razer-axon.sh`) запускает его именно с этим ключом — без него приложение и не обязано
показывать окно. Повторный замер сделан «по всем правилам»:

* применён per-app оверрайд `HKCU\Software\Wine\AppDefaults\msedgewebview2.exe → Version=win7`
  при `win10` у остального префикса (проверено в реестре: значение легло);
* выставлены `HardwareAccelerationModeEnabled=0` в трёх ветках политик Edge;
* заданы `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`, `LIBGL_ALWAYS_SOFTWARE=1`,
  `GALLIUM_DRIVER=llvmpipe`;
* запуск: `wine RazerAxon.exe -showui`.

Результат через 55 с: процессы живы (`RazerAxon.exe -wrongaccess` и
`RazerAxon.exe -wrongaccess -showui`), **окна нет ни одного** — ни видимого, ни
скрытого. Проверено тремя независимыми способами:

```
wmctrl -l                                   → только Steam
xdotool search --all --onlyvisible          → ни одного окна с Razer/Axon
xwininfo -root -tree | grep -i 'razer|axon' → пусто
```

Лог приложения останавливается ровно на входе:

```
Program.cs:TryLoginAsync   Start userLogin        ← и дальше ничего
UserManager.cs:RegisterForUpdateAsync   register update failed  (Razer.Updater.UpdateClient)
UserManager.cs:RegisterForUpdateAsync   Check update failed
```

⭐ **Вывод замера (ответ на вопрос «нужен ли Razer Central»): нужен, и не для входа
в аккаунт, а для показа окна вообще.** `RazerAxon.exe` не создаёт окно **до** того,
как отработает `TryLoginAsync`, а тот упирается в именованный канал Razer Central и
висит на нём. То есть «пустое окно» — не тот симптом, который у нас есть: у нас
**нет никакого окна**, и WebView2 тут ни при чём — до него дело просто не доходит.

Отсюда следует и порядок дальнейших работ: сперва заставить кого-то отвечать на
канале Razer Central, и только потом имеет смысл проверять путь WebView2/DirectComposition.

### Заход 10 — Razer Central 7.23.0.1220 ставится под Wine, и `/silent` работает

Дата: 2026-08-12. Префикс: `~/.wine-axon` (создан начисто, `WINEARCH=win64`).

Заход 7 сделал вывод «`/silent` не соблюдается» — вывод оказался **неверным по причине**.
`/silent` соблюдается прекрасно; в заходе 7 его перебивало модальное окно
`Technology Required`, которое установщик поднимает **до** разбора своих ключей, когда
не находит настоящего .NET Framework. Убираем причину — исчезает и симптом.

Порядок, проверенный живьём:

```bash
export WINEPREFIX="$HOME/.wine-axon"
WINEARCH=win64 wineboot --init          # свежий префикс: win10, build 19045
winetricks -q dotnet48                  # ~14 мин
wine winecfg -v win10                   # ОБЯЗАТЕЛЬНО после dotnet48
wine RazerCentral_v7.23.0.1220.exe /silent
```

Побочный эффект dotnet48, предсказанный заходом 8, теперь подтверждён числом:

```
до  winecfg -v win10:  "CurrentBuild"="7601"    ← это оставил dotnet48
после                  "CurrentBuild"="19045"
```

Результат установки Central — **успех, полностью тихо, ни одного окна**:

```
C:\Program Files (x86)\Razer\Razer Services\Razer Central\   294 МБ
    RazerCentralService.exe
    Razer Central.exe
    Razer Updater.exe
    CefSharp.BrowserSubprocess.exe
    ndp48-web.exe                 (тот самый веб-установщик .NET, который он звал в заходе 7)
    локали: de-DE en-US es-ES fr-FR ja-JP ko-KR pt-BR ru-RU zh-CN zh-CHT
```

⭐ **Служба регистрируется САМА, и имя у неё другое, чем написано в README проекта.**
README предлагает `sc create RazerCentralService …` — этого делать не надо, и по этому
имени служба не найдётся. Установщик заводит её сам:

```
[System\ControlSet001\Services\RzActionSvc]
    "DisplayName" = "Razer Central Service"
    "ImagePath"   = "C:\Program Files (x86)\Razer\Razer Services\Razer Central\RazerCentralService.exe"
    "Start"       = dword:00000002      (авто-запуск)
    "Type"        = dword:00000010      (собственный процесс)
```

Запуск и проверка:

```
wine sc start RzActionSvc
wine sc query RzActionSvc
    SERVICE_NAME: RzActionSvc
    STATE : 4  RUNNING
```

⚠️ **Практическая ловушка для скрипта и лаунчера:** служба живёт ровно столько, сколько
живёт `wineserver` префикса. Через несколько секунд бездействия wineserver гасится и
уносит `RazerCentralService.exe` с собой — проверено: сразу после `sc query … RUNNING`
в префиксе не осталось ни одного процесса Wine. Поэтому службу нужно поднимать
**в том же сеансе**, в котором запускается Axon, а не «один раз при установке».

## Гипотеза о версии Windows

Пользовательская формулировка: Wine создаёт префикс с Windows 7 по умолчанию, а Axon
требует 10 или 11; при семёрке установщик молча не запускается.

**Итог проверки: гипотеза верна по СЛЕДСТВИЮ (win7 действительно не даёт поставить,
win10/11 дают) и неверна по ПРИЧИНЕ (Wine тут ни при чём — умолчание давно win10).**

Проверок оказалось две, и упирается всё в ДВЕ независимые привязки к версии Windows:

| # | Кто проверяет | Что происходит при win7 | Замер |
|---|---|---|---|
| 1 | сервер Razer `manifest3.razerapi.com` | `osver=7` → пустой каталог → онлайн-обёртка пишет «доступ к серверу невозможен» | май 2026 |
| 2 | сам Inno-setup (`MinVersion`) | модальное `This program does not support the version of Windows your computer is running`, установка не идёт | заход 5, снимок |

Ниже — разбор по пунктам.

1. Что Windows 7 ломает установку — **правда**, и механизм задокументирован ещё в мае:
   движок онлайн-обёртки шлёт на `manifest3.razerapi.com` параметр `osver=7`, сервер
   Razer легитимно отвечает **пустым каталогом** `{"data":{"items":[]}}` (Axon требует
   Win10+), а обёртка трактует пустой каталог как «услуга отключена» и показывает
   зелёный экран «доступ к серверу невозможен». Ставить, соответственно, нечего.
2. Что семёрку ставит **сам Wine** — **неправда**. Свежий префикс wine-11.15 уже
   Windows 10 (замер в заходе 1).
3. ⭐ Настоящий источник семёрки — **`winetricks dotnet48`**: он в качестве побочного
   эффекта переставляет версию префикса на win7 (это прямо отмечено в майском
   документе: «`winecfg -v win10` ИМЕННО после dotnet48, т.к. он сбрасывает версию
   на win7»). То есть семёрка появляется не при создании префикса, а на шаге
   установки .NET Framework — и бьёт по тому пути установки, который через .NET
   обёртку и идёт.

Практический вывод: **порядок шагов важнее самих шагов.** Если ставить через онлайн-
обёртку, `winetricks -q dotnet48` обязан идти ПЕРЕД возвратом версии на win10, иначе
получаем «молча не ставится». Если же ставить Inno-setup напрямую (заход 2), вопрос
версии Windows на этапе установки не возникает вовсе.

## Рецепт установки

Проверен живьём 2026-08-11 на wine-11.15, от полностью чистого состояния. Требуется
работающий интернет (шаг 2 качает WebView2 с серверов Microsoft, ~190 МБ на входе,
670 МБ на диске).

```bash
# 1. Свежий 64-битный префикс. Ничего в нём править НЕ нужно:
#    wine-11.15 и так выставляет Windows 10 (build 19045).
export WINEPREFIX="$HOME/.local/share/openaxon/prefix"
WINEARCH=win64 wineboot --init

# 2. Установка приложения напрямую из Inno-setup, в тихом режиме.
#    Параметры — ровно те, что Razer публикует в собственном манифесте
#    (опечатка /SUPRESSMSGBOXES — их, оставлена как есть).
wine /путь/к/RazerAxonSetup_2.9.1.0.exe \
     /SP- /VERYSILENT '/DIR=C:\Program Files (x86)\Razer\Razer Axon' \
     /SUPRESSMSGBOXES /NORESTART

# 3. Дождаться завершения — setup сам подтянет и поставит WebView2 Runtime.
#    Ориентир: ~4 минуты; готовность видна по появлению
#    "Program Files (x86)/Microsoft/EdgeWebView" (~670 МБ)
#    и по исчезновению процессов RazerAxonSetup из ps.
```

Проверка результата:

```bash
wine reg query \
  'HKLM\Software\Microsoft\Windows\CurrentVersion\Uninstall\Razer Axon_is1' /v DisplayVersion
# → DisplayVersion    REG_SZ    2.9.1.0
```

### Где взять `RazerAxonSetup_2.9.1.0.exe`

Ссылка публикуется самим Razer в манифесте и берётся без авторизации:

```bash
HASH=$(curl -s 'https://discovery3.razerapi.com/api/v1/endpoints?tag=prod' \
       | grep -oP '"hash":"\K[^"]+')
curl -s "https://manifest3.razerapi.com/api/v1/releases/$HASH/tags/prod/products?os=WINDOWS&osver=11&arch=64&mfr=Generic-MFR&model=Generic-MDL0&sku=Generic-SKU&l=en-US"
# → items[name=="Sequoia"].modules[name=="Razer Axon"].download_url  (+ MD5 для сверки)
```

⚠️ `osver` в этом запросе обязан быть `10` или `11`: при `osver=7` сервер Razer отдаёт
пустой каталог, и ссылку взять неоткуда (см. раздел про версию Windows).

### Чего в рецепте НЕТ и почему

| Шаг из майского рецепта (2.6.2.0) | Нужен для 2.9.1.0 | Почему |
|---|---|---|
| `winetricks -q dotnet48` | **нет** | .NET Framework 4.8 нужен только движку ОНЛАЙН-обёртки; Inno-setup обходится без него |
| `winecfg -v win10` | **нет** | свежий префикс wine-11.15 уже win10 |
| ручная установка WebView2 Evergreen | **нет** | setup 2.9.1.0 сам вызывает вшитый `MicrosoftEdgeWebview2Setup.exe /silent /install` |
| запуск `RazerAxonInstaller.exe` (WPF-обёртка) | **нет** | её интерфейс под Wine крашится на экране лицензии; обходится целиком |

## Дефекты Wine (кандидаты в апстрим)

Правки для игр и Windows-программ подаются в **Wine**, не в Proton (Proton — форк Wine,
правки текут вниз, а не вверх). Здесь — только то, что подтверждено замером, с указанием,
что именно это ломает.

⭐ **Главное: установку 2.9.1.0 не блокирует ни один дефект Wine.** Setup ставится на
голом префиксе. Всё перечисленное ниже — либо шум, либо помехи на смежных путях.

### Д1. `wineserver -w` не может дождаться резидентного `MicrosoftEdgeUpdate.exe /c`

**Подтверждено, заход 8.** Не дефект Wine в узком смысле, но практическая ловушка,
которая стоила майскому разбору неверного вывода («известный баг winetricks»). Установка
WebView2 оставляет в префиксе вечный процесс Edge Update, после чего любой verb winetricks
встаёт намертво. Куда это годится: **заметка в winetricks** (снимать резидент Edge Update
перед `wineserver -w`) и/или строка в AppDB.

Доказательство: `MicrosoftEdgeUpdate.exe /c` жив 1010 с; снятие ровно этого PID
немедленно разблокировало winetricks и установка .NET продолжилась.

### Д2. `richedit`: неполный разбор RTF при показе лицензии

```
err:richedit:ReadColorTbl malformed entry           (×6)
err:richedit:ReadStyleSheet skipping optional destination   (×9)
```

Возникает, когда Inno грузит текст лицензии. На установку не влияет (текст всё равно не
показывается при `/VERYSILENT`), но это честный пробел в реализации `riched20` —
таблица цветов и таблица стилей RTF разбираются не полностью. Кандидат в Wine как
маленький самостоятельный баг с воспроизведением на конкретном RTF.

### Д3. `shell32`: `IShellLinkW::QueryInterface` возвращает `E_NOINTERFACE`

```
err:shell:IShellLinkW_fnQueryInterface -- Interface: E_NOINTERFACE   (×4)
```

Ловится при старте `RazerAxon.exe` (создание/чтение ярлыка). Требует уточнения, какой
именно IID запрашивается (нужен прогон с `WINEDEBUG=+shell,+ole`), после чего это
готовый репорт: объект ярлыка Wine не отдаёт интерфейс, который отдаёт настоящий Windows.

### Д4. `combase`: нет WinRT-класса телеметрии

```
err:combase:RoGetActivationFactory Failed to find library for
    L"Windows.System.Diagnostics.Telemetry.PlatformTelemetryClient"
err:ole:com_get_class_object no class object {cecddd22-2e72-4832-9606-a9b0e5e344b2}
    could be created for context 0x17
err:ole:CoSetProxyBlanket -- failed with 0x80004002
```

Изнутри Edge Update. Безвредно (телеметрия), но показывает отсутствующий WinRT-класс.
Низкий приоритет.

### Д5. Стабы, замеченные по дороге

```
fixme:seh:WerRegisterCustomMetadata (L"EdgeUpdateDllVersion", …) stub
fixme:clusapi:ClusterEnum / ClusterCloseEnum / CloseCluster (DEADBEEF, …) stub!
fixme:advapi:DecryptFileW (…) stub
fixme:nls:get_dummy_preferred_ui_language … returning a dummy value
fixme:msi:internal_ui_handler internal UI not implemented for message 0x0b000000
```

Ни один не помешал установке. Записаны для полноты.

### Ранее известные (из майского разбора, к 2.9.1.0 не перепроверялись)

* **Краш WPF-интерфейса онлайн-обёртки** на переходе с экрана лицензии:
  `Razer.Installer.UI.Language.Attached.TextBlockTextPlugin.Update()` →
  `TextBlock.EnsureComplexContent()` → `0x80131623`. Обходится тем, что обёртка вообще
  не используется (см. рецепт), поэтому в этом заходе не воспроизводилось.
* **WebView2 и DirectComposition**: `DCompositionCreateDevice` возвращает `E_NOTIMPL`,
  из-за чего viz-процесс Chromium бьёт CHECK при версии Windows ≥ 8.1 и кадр не доходит
  до окна. Обход — per-app оверрайд `Version=win7` для `msedgewebview2.exe` при
  сохранении win10 для остального префикса. **Это самый весомый кандидат в апстрим**
  из всей истории проекта.

### Не дефекты Wine, а особенности самого Razer

Отмечаю отдельно, чтобы не подать в Wine то, что Wine не касается:

1. **Опечатка `/SUPRESSMSGBOXES`** вместо `/SUPPRESSMSGBOXES` в манифесте Razer —
   ключ не срабатывает, окна сообщений не подавляются, и «тихая» установка при отказе
   встаёт на невидимом модальном окне.
2. **`MinVersion` в Inno-setup** режет Windows 7 — это осознанное требование Razer
   (Axon заявлен для Windows 10+), а не поломка.
3. **`/silent` у RazerCentral не соблюдается** — установщик всё равно показывает окна.
